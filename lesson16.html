Lezione 16: Metodo PUT

Sviluppo REST API: Costruire, Testare, Risolvere Problemi

Il metodo PUT viene utilizzato nelle REST API per aggiornare una risorsa esistente. A differenza del metodo POST, che crea nuovi dati, PUT modifica dati che esistono già sul server.

I client inviano informazioni aggiornate all'API e il server sostituisce o aggiorna la risorsa esistente con i nuovi valori forniti nella richiesta.

Scopo del Metodo PUT

PUT viene utilizzato quando un client deve aggiornare una risorsa specifica. La richiesta include normalmente l'identificatore della risorsa insieme ai nuovi dati.

Esempi comuni includono:

  • Aggiornare informazioni su un prodotto
  • Modificare i dettagli di un cliente
  • Cambiare lo stato di un ordine
  • Modificare le informazioni del profilo utente

Esempio di Richiesta PUT

Una richiesta PUT viene generalmente inviata a un endpoint specifico che include l'identificatore della risorsa da aggiornare.

PUT /api/products/5

Corpo della richiesta:

{ "id": 5, "name": "Wireless Mouse", "price": 22, "stock": 60 }

Questa richiesta indica al server di aggiornare il prodotto con ID 5 utilizzando i nuovi valori forniti.

Elaborazione sul Server

Quando il server riceve una richiesta PUT, di solito esegue i seguenti passaggi:

  • Verificare che la risorsa esista
  • Validare i dati ricevuti
  • Aggiornare il record nel database
  • Restituire una risposta al client

Esempio di Risposta

Se l’aggiornamento ha successo, il server può restituire la risorsa aggiornata oppure un messaggio di conferma.

{ "id": 5, "name": "Wireless Mouse", "price": 22, "stock": 60 }

Codici di Stato HTTP per PUT

  • 200 OK – Risorsa aggiornata con successo
  • 204 No Content – Aggiornamento riuscito senza corpo di risposta
  • 400 Bad Request – Dati non validi
  • 404 Not Found – Risorsa non trovata

Testare le Richieste PUT

Gli sviluppatori possono testare le richieste PUT utilizzando strumenti come Postman. Questi strumenti permettono di inviare dati JSON nel corpo della richiesta e verificare la risposta dell’API.

Esempio di endpoint testato in Postman:

https://localhost:5001/api/products/5

Buone Pratiche

  • Validare sempre i dati ricevuti
  • Assicurarsi che la risorsa esista prima di aggiornarla
  • Restituire codici di stato HTTP appropriati
  • Utilizzare strutture JSON chiare e coerenti

Seguire queste pratiche aiuta a mantenere una REST API affidabile e prevedibile.

Prossimi Passi

Dopo aver implementato il metodo PUT, il passo successivo è implementare il metodo DELETE, che consente di rimuovere risorse e completare la piena funzionalità CRUD all’interno dell’API.
