Lezione 15: Metodo POST

Sviluppo REST API: Costruire, Testare, Risolvere Problemi

Il metodo POST viene utilizzato nelle REST API per creare nuove risorse sul server. A differenza del metodo GET, che recupera dati, POST invia dati dal client al server affinché venga creato un nuovo record.

Le richieste POST includono normalmente dati nel corpo della richiesta, di solito formattati come JSON. Il server elabora i dati, esegue la validazione e memorizza la nuova risorsa nel database.

Scopo del Metodo POST

Il metodo POST consente ai client di inviare nuovi dati al server. Questo viene comunemente utilizzato quando si creano nuovi record in un sistema.

Esempi tipici includono:

  • Creare un nuovo prodotto
  • Registrare un nuovo utente
  • Aggiungere un nuovo ordine
  • Inviare un modulo

Esempio di Richiesta POST

Una richiesta POST invia normalmente dati JSON nel corpo della richiesta.

POST /api/products

Corpo della richiesta:

{ "name": "Wireless Mouse", "price": 25, "stock": 50 }

Questa richiesta chiede al server di creare un nuovo prodotto utilizzando i dati forniti.

Elaborazione sul Server

Quando il server riceve una richiesta POST, di solito esegue diversi passaggi:

  • Validare i dati di input
  • Creare un nuovo oggetto basato sul modello
  • Salvare il record nel database
  • Restituire una risposta al client

Esempio di Risposta

Se l’operazione ha successo, il server può restituire una risposta come questa:

{ "id": 10, "name": "Wireless Mouse", "price": 25, "stock": 50 }

La risposta spesso include la risorsa appena creata insieme al suo identificatore generato.

Codici di Stato HTTP per POST

  • 201 Created – Risorsa creata con successo
  • 400 Bad Request – Dati della richiesta non validi
  • 500 Internal Server Error – Errore di elaborazione del server

Restituire i codici di stato corretti aiuta i client a comprendere il risultato della richiesta.

Testare le Richieste POST

Le richieste POST possono essere testate utilizzando strumenti come Postman. Gli sviluppatori possono inviare dati JSON nel corpo della richiesta e osservare la risposta dell’API.

Esempio di endpoint testato in Postman:

https://localhost:5001/api/products

Buone Pratiche

  • Validare i dati di input prima di salvarli
  • Restituire codici di stato HTTP appropriati
  • Utilizzare strutture JSON chiare
  • Garantire che le operazioni sul database siano sicure

Seguire queste pratiche garantisce che gli endpoint POST rimangano affidabili e sicuri nei sistemi REST API.

Prossimi Passi

Dopo aver implementato il metodo POST, il passo successivo è implementare altri metodi come PUT e DELETE, consentendo la piena funzionalità CRUD all’interno della REST API.
