Lezione 17: Metodo DELETE

Sviluppo REST API: Costruire, Testare, Risolvere Problemi

Il metodo DELETE nelle REST API viene utilizzato per rimuovere una risorsa esistente dal server. Consente ai client di richiedere l'eliminazione di un record specifico dal sistema.

Questo metodo è una parte essenziale delle operazioni CRUD (Create, Read, Update, Delete) ed è generalmente utilizzato quando i dati non devono più esistere nel database.

Scopo del Metodo DELETE

Il metodo DELETE consente al client di rimuovere una risorsa identificata da un identificatore univoco. Questa operazione aiuta a mantenere dati puliti e accurati nel sistema.

Esempi comuni includono:

  • Eliminare un prodotto da un sistema di inventario
  • Rimuovere un account utente
  • Annullare un ordine
  • Eliminare record obsoleti

Esempio di Richiesta DELETE

Le richieste DELETE vengono generalmente inviate a un endpoint specifico che include l'identificatore della risorsa da rimuovere.

DELETE /api/products/5

Questa richiesta chiede al server di eliminare il prodotto con ID 5.

Elaborazione sul Server

Quando l'API riceve una richiesta DELETE, il server normalmente esegue i seguenti passaggi:

  • Verificare che la risorsa esista
  • Controllare i permessi o l'autorizzazione
  • Rimuovere la risorsa dal database
  • Restituire una risposta appropriata al client

Esempio di Risposta

In molti casi, le operazioni DELETE restituiscono una risposta di conferma invece dell'oggetto eliminato.

{ "message": "Prodotto eliminato con successo" }

Codici di Stato HTTP per DELETE

  • 200 OK – Risorsa eliminata con successo
  • 204 No Content – Risorsa eliminata senza corpo di risposta
  • 404 Not Found – La risorsa non esiste
  • 401 Unauthorized – Utente non autorizzato a eliminare la risorsa

Testare le Richieste DELETE

Gli sviluppatori testano comunemente le richieste DELETE utilizzando strumenti come Postman. Questi strumenti permettono di inviare richieste HTTP all'API e verificare che la risorsa sia stata rimossa.

Esempio di endpoint testato in Postman:

https://localhost:5001/api/products/5

Buone Pratiche

  • Verificare che la risorsa esista prima di eliminarla
  • Implementare controlli di autorizzazione adeguati
  • Restituire codici di stato chiari e significativi
  • Considerare l'uso dei soft delete per dati critici

I soft delete sono una pratica comune in cui i record vengono contrassegnati come eliminati invece di essere rimossi permanentemente. Questo approccio aiuta a mantenere dati storici e supporta il recupero se necessario.

Conclusione

Il metodo DELETE completa il ciclo CRUD nello sviluppo delle REST API. Insieme a GET, POST e PUT, consente agli sviluppatori di creare API completamente funzionali capaci di gestire i dati in modo efficiente.
