Lezione 21: Definire Rotte Personalizzate nei Metodi GET

Sviluppo REST API: Costruire, Testare, Risolvere Problemi

Nello sviluppo di REST API, i metodi GET vengono utilizzati per recuperare risorse. Mentre le rotte GET standard permettono il recupero di base tramite ID o l'elenco di tutti gli elementi, definire rotte personalizzate offre alla tua API maggiore flessibilità e potenza.

Perché Utilizzare Rotte GET Personalizzate?

Le rotte personalizzate consentono ai client di accedere a dati specifici o eseguire query complesse senza richiedere più passaggi di filtraggio dal lato client.

  • Fornire endpoint per query specifiche
  • Organizzare le risorse in una struttura logica
  • Ridurre il filtraggio e l'elaborazione dei dati lato client
  • Migliorare l'usabilità e la chiarezza dell'API

Esempio: Rotta GET Personalizzata

Supponiamo di avere un'API di prodotti. Una rotta personalizzata può restituire solo i prodotti attivi di una categoria:

GET /api/products/active/electronics

Qui, active e electronics fanno parte della rotta, permettendo al server di restituire direttamente dati filtrati.

Implementazione di Rotte Personalizzate in ASP.NET Core

In ASP.NET Core, puoi definire rotte GET personalizzate utilizzando l'attributo di routing:

[HttpGet("active/{category}")] public IActionResult GetActiveProducts(string category) { var products = _db.Products .Where(p => p.IsActive && p.Category == category) .ToList(); return Ok(products); }

Questo approccio associa automaticamente l'URL /api/products/active/electronics al metodo GetActiveProducts.

Buone Pratiche

  • Mantenere le rotte intuitive e descrittive
  • Utilizzare nomi di risorse (sostantivi) ed evitare verbi nelle rotte
  • Documentare chiaramente tutte le rotte personalizzate per gli utenti dell'API
  • Assicurarsi che i parametri della rotta siano validati

Conclusione

Definire rotte personalizzate nei metodi GET rende la tua REST API più flessibile e più facile da utilizzare per i client. Permette al server di gestire efficientemente query complesse e mantiene la struttura dell'API organizzata e logica.
