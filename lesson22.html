Lezione 22: Differenze tra PUT e PATCH nelle REST API

Sviluppo REST API: Costruire, Testare, Risolvere Problemi

Nello sviluppo di REST API, sia i metodi PUT che PATCH vengono utilizzati per aggiornare risorse, ma si comportano in modo diverso e hanno scopi distinti.

Metodo PUT

Il metodo PUT viene utilizzato per **aggiornamenti completi** di una risorsa. Quando un client invia una richiesta PUT, l'intera risorsa viene sostituita con i nuovi dati forniti.

PUT /api/products/45 { "name": "New Product Name", "price": 99.99, "category": "Electronics", "stock": 50 }

Tutti i campi devono essere inclusi, anche se alcuni valori rimangono invariati, perché la risorsa viene completamente sostituita.

Metodo PATCH

Il metodo PATCH viene utilizzato per **aggiornamenti parziali**. Permette di modificare solo campi specifici senza influenzare il resto della risorsa.

PATCH /api/products/45 { "price": 79.99, "stock": 60 }

In questo esempio, vengono aggiornati solo price e stock, mentre tutti gli altri campi rimangono invariati.

Differenze Principali

  • PUT: Sostituzione completa della risorsa, tutti i campi sono richiesti.
  • PATCH: Aggiornamento parziale, sono necessari solo i campi da modificare.
  • PUT: Sovrascrive completamente la risorsa.
  • PATCH: Aggiorna solo i campi specificati.
  • Casi d'uso: PUT per sostituire risorse, PATCH per aggiornamenti rapidi o modifiche minori.

Buone Pratiche

  • Usare PUT quando il client possiede la rappresentazione completa della risorsa.
  • Usare PATCH per aggiornamenti incrementali per ridurre il trasferimento di dati e possibili errori.
  • Documentare chiaramente quali endpoint supportano PUT o PATCH.
  • Validare i dati di input per evitare sovrascritture non intenzionali.

Conclusione

Comprendere le differenze tra PUT e PATCH garantisce una corretta progettazione delle API, previene la perdita accidentale di dati e migliora l'interazione tra client e server.
